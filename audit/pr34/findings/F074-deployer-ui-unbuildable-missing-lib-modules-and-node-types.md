## Summary

`contracts/deployer-ui` does not build at `f4fc4af`. Verified by actually
running `npm ci` (succeeded, 546 pkgs) then `npx tsc -b` (the type-check half of
`npm run build`).

## Evidence

**Missing `src/lib` modules — the directory does not exist.** Import
specifiers:
- `src/components/MerkleTreeBuilder.tsx:4` → `../lib/merkle`
  (`buildRoot, proofFor, sortHexAscending`)
- `src/components/MerkleTreeBuilder.tsx:5` → `../lib/leaf` (`lockLeafEvm`)
- `src/components/RootSigner.tsx:5` → `../lib/leaf` (`rootUpdateDigest`)
- `src/components/RootSigner.tsx:6` → `../lib/recover`
  (`ceremonySignCommand, recoverFromRawDigest`)

`ls src/lib` → "No such file or directory". `src/` contains only App.tsx,
createx.ts, deploy.ts, main.tsx, salt.ts, wagmi.ts, styles.css, vite-env.d.ts,
and `components/`.

**`npx tsc -b` errors (verbatim):**
```
src/components/MerkleTreeBuilder.tsx(4,55): TS2307: Cannot find module '../lib/merkle'
src/components/MerkleTreeBuilder.tsx(5,29): TS2307: Cannot find module '../lib/leaf'
src/components/RootSigner.tsx(5,34):        TS2307: Cannot find module '../lib/leaf'
src/components/RootSigner.tsx(6,59):        TS2307: Cannot find module '../lib/recover'
scripts/generate-bytecode.ts(5,57): TS2307: Cannot find module 'node:fs'
scripts/generate-bytecode.ts(6,34): TS2307: Cannot find module 'node:path'
scripts/generate-bytecode.ts(7,31): TS2307: Cannot find module 'node:url'
scripts/generate-bytecode.ts(9,53): TS2339: Property 'url' does not exist on type 'ImportMeta'
scripts/generate-bytecode.ts(19,5): TS2580: Cannot find name 'process' ... Try `npm i --save-dev @types/node`
scripts/*.ts:                        TS2584: Cannot find name 'console' (multiple)
```

**Node-typings root cause:** `@types/node` is not in package.json
devDependencies and not installed; no tsconfig has a `"types"` key, and
`tsconfig.node.json` sets `lib: ["ES2023"]` (no DOM), so even `console` is
unresolved.

**Nuance (not part of the defect):** `tsc -b` also flags `../abis`, `./abis`,
`./bytecode`, but these are generated by `scripts/generate-bytecode.ts` from
forge artifacts (gitignored) and resolve after `forge build` + the `prebuild`
hook — the reviewer correctly excluded them. A clean `npm run build` also
requires `forge build` first (the `prebuild` hook hard-exits "Run `forge build`
first" otherwise). The `lib/*` modules and node typings are generated by
nothing and remain broken.

## Severity / scope

Peripheral tooling — the off-chain Vite/React deployer helper (build Merkle
roots, sign root updates, run deploy/burn/claim). Not part of the on-chain
bridge contracts or the Rust/Malachite consensus code in the audit's core
scope. The UI is completely unbuildable/unusable as shipped (P1 for the tool
itself), but it does not affect deployed-contract correctness or security
properties. **Not a core-scope merge blocker.**

## Fix

1. Add `src/lib/merkle.ts` (`buildRoot`, `proofFor`, `sortHexAscending`),
   `src/lib/leaf.ts` (`lockLeafEvm`, `rootUpdateDigest`), `src/lib/recover.ts`
   (`ceremonySignCommand`, `recoverFromRawDigest`) — matching the on-chain
   leaf/root/digest encoding.
2. Add `@types/node` to devDependencies and set `"types": ["node"]` in
   `tsconfig.node.json`.
3. Document the `forge build` prerequisite for the generated
   `src/abis.ts` / `src/bytecode.ts`.

## PoC

The build itself is the reproduction: from `contracts/deployer-ui`, `npm ci`
then `npx tsc -b` emits the TS2307/TS2339/TS2580 errors above. No separate red
test needed.
